# 🌅 서해링

> 흩어진 학교 이벤트를 한 곳에서, 휴대폰으로

우리 학교 학생들은 교내 행사 신청 기간에 공지가 여러 곳(게시판, 단톡방, 선생님 전달)에 흩어져 있어서 신청을 놓치곤 해요.
**서해링**은 학생 참여 이벤트를 날짜별·달력으로 한곳에 모아 보여 주는 학교 이벤트 게시판이에요.

## 바로 열기

👉 **https://seohae-team6.github.io/team6-event/**

- 설치 없이 주소만 열면 돼요. 휴대폰, 컴퓨터 모두 돼요.
- 로그인, 회원가입이 없고 개인정보를 저장하지 않아요.
- 메뉴 → **링크 · QR코드 공유**에서 QR코드를 찍어도 열려요.
- 휴대폰 홈 화면에 앱처럼 놓으려면: 아이폰은 사파리 **공유 → 홈 화면에 추가**, 안드로이드는 크롬 **⋮ → 홈 화면에 추가**.

## 주요 기능

| 기능 | 설명 |
| --- | --- |
| 날짜별 목록 | 다가오는 순서로 정리하고 D-day를 보여 줘요 |
| 달력 | 이벤트가 있는 날을 색으로 표시해요. 며칠 동안 하는 행사도 기간으로 보여요 |
| 검색 | 이벤트 이름으로 바로 찾아요 |
| 상세 화면 | 날짜, 시간, 장소, 설명, **신청 받는 곳**을 한눈에 봐요 |
| 만료된 이벤트 | 날짜가 끝난 이벤트는 아래 '만료된 이벤트' 칸으로 내려가고, 삭제할 때까지 남아 있어요 |
| 링크 · QR코드 공유 | 링크를 복사하거나 QR코드 그림을 저장할 수 있어요 |

## 쓰는 법

### 학생
1. 주소나 QR코드로 서해링을 열어요.
2. **날짜별** 또는 **달력** 탭에서 이벤트를 찾아요. 이름으로 검색해도 돼요.
3. 이벤트를 누르고 **신청 받는 곳**을 확인해서 신청해요.

### 학생회 (이벤트를 올리는 사람)
1. **+ 등록**을 누르고 코드를 입력해요. 달력에서 날짜를 누르고 **+ 이 날짜에 등록**을 눌러도 돼요.
2. 이벤트 이름, 날짜, 신청 받는 곳 등을 적고 **등록하기**를 눌러요.
3. 고치거나 지우려면 이벤트를 눌러 **수정** / **삭제**를 누르고 코드를 입력해요. 달력에서 날짜를 누르면 아래에도 수정·삭제 버튼이 있어요.

> 코드는 등록·수정·삭제할 때마다 물어봐요. 대문자와 소문자를 구분해요. 코드는 학생회끼리만 알고 있어요.

## 사용한 기술

- **HTML, CSS, JavaScript**: 화면과 기능 (CSS, JS, Firebase 설정까지 모두 `index.html` 한 파일 안에 있어요)
- **GitHub Pages**: 사이트 주소 (무료)

## 파일

# 관리자용 안내

아래는 서해링을 관리하는 사람을 위한 내용이에요. 서해링은 이미 설정이 끝나 있어요. 처음부터 다시 만들 때나, 문제가 생겼을 때 봐요.

## 처음부터 설정하는 방법

### 1. Firebase 프로젝트 만들기
1. https://console.firebase.google.com 에 Google 계정으로 들어가요.
2. **프로젝트 추가** → 이름은 `seohaering`처럼 아무거나 → Google 애널리틱스는 꺼도 돼요.

### 2. 웹 앱 등록하고 설정값 복사하기
1. 프로젝트 첫 화면에서 **`</>` (웹)** 아이콘을 눌러요.
2. 앱 이름 `서해링` 입력 → **앱 등록** (Firebase 호스팅 체크는 안 해도 돼요).
3. 나오는 코드에서 `firebaseConfig = { ... }` 안의 값들을 복사해요.
4. `index.html`을 메모장으로 열고 `FIREBASE_CONFIG`를 찾아(Ctrl+F) 같은 이름의 값들을 복사한 값으로 바꿔요.
   (지금 서해링은 이미 채워져 있어요. 새 프로젝트를 만들 때만 바꿔요.)

### 3. Firestore(저장소) 만들기
1. 왼쪽 메뉴 **빌드 → Firestore Database → 데이터베이스 만들기**.
2. 위치는 **asia-northeast3 (서울)**, 모드는 **프로덕션 모드**로 시작해요.
3. 만들어지면 **규칙** 탭에서 원래 내용을 지우고 `firestore.rules` 내용을 그대로 붙여 넣은 뒤 **게시**를 눌러요.
   (윈도우에서 `firestore.rules`가 안 열리면 마우스 오른쪽 버튼 → **연결 프로그램 → 메모장**)

### 4. 관리자 계정(코드) 만들기
1. 왼쪽 메뉴 **빌드 → Authentication → 시작하기**.
2. **로그인 방법** 탭 → **이메일/비밀번호** → 사용 설정 → 저장.
3. **사용자** 탭 → **사용자 추가**
   - 이메일: `admin@seohaering.app`
   - 비밀번호: 이 비밀번호가 웹앱의 **코드**가 돼요. **8자 이상, 영어와 숫자를 섞어서** 정해요. 코드는 파일에 적히지 않으니 관리자끼리만 알고 있어요.
4. **설정** 탭 → **사용자 작업** → **생성(가입) 사용 설정**의 체크를 꺼요.
   (다른 사람이 마음대로 계정을 만들지 못하게 막는 설정이에요.)

### 5. GitHub Pages에 올리기
1. https://github.com 에서 **New repository** → 이름 정하기(지금 서해링은 `team6-event`) → **Public** → 만들기.
2. **Add file → Upload files**로 `index.html`, `firestore.rules`, `README.md`를 올리고 **Commit changes**.
3. 저장소의 **Settings → Pages**
   - Source: **Deploy from a branch**
   - Branch: **main** / **/(root)** → Save
4. 1~2분 뒤 위쪽에 주소가 나와요: `https://아이디.github.io/저장소이름/`

### 6. 열어 보고 첫 이벤트 등록하기
1. 휴대폰으로 주소를 열어요. "아직 등록된 이벤트가 없어요"가 보이면 연결 성공이에요.
2. **+ 등록** → 4단계에서 정한 비밀번호(코드) 입력 → 첫 이벤트를 올려요.
3. 이벤트를 누르면 아래에 **수정**, **삭제** 버튼이 있어요. 누를 때마다 코드를 물어봐요.

## 코드 바꾸기

1. Firebase 콘솔 → Authentication → **사용자** 탭 → `admin@seohaering.app` 줄 오른쪽 ⋮ → **계정 삭제**
2. **사용자 추가** → 이메일 `admin@seohaering.app`, 비밀번호에 **새 코드** 입력

'Reset password(비밀번호 재설정)'는 메일을 보내는 방식인데, `admin@seohaering.app`은 실제로 없는 메일 주소라서 메일이 오지 않아요. 그래서 지우고 다시 만드는 방법을 써요. 이메일만 같으면 보안 규칙은 그대로 작동하고, 올려 둔 이벤트도 지워지지 않아요.

## 고친 파일 올리기

1. 저장소에서 **Add file → Upload files** → 고친 파일을 끌어다 놓고 **Commit changes**.
2. 사이트에 반영되기까지 1~2분, 브라우저가 예전 화면을 기억하면 최대 10분쯤 걸려요.
3. 바로 보고 싶으면 PC는 **Ctrl+F5**, 휴대폰은 주소 끝에 `?v=2`처럼 붙여서 열어요.
4. 올리기 전에 컴퓨터의 파일이 최신인지 파일 크기로 확인해요. 예전 파일로 덮어쓰지 않게 조심해요.

## 안전하게 쓰기

- 코드는 관리자끼리만 알고, 새어 나가면 바로 바꿔요.
- Firebase 프로젝트를 만든 Google 계정과 GitHub 계정에 **2단계 인증**을 켜요.
- `index.html` 안의 Firebase 설정값(`FIREBASE_CONFIG`)은 공개돼도 괜찮아요. 누가 글을 쓰고 지울 수 있는지는 `firestore.rules`가 지켜 줘요.

## 문제가 생기면

| 화면에 나오는 말 | 고치는 방법 |
| --- | --- |
| 서해링 게시판에 연결되지 않았어요 | 인터넷 연결을 확인해요. 계속 그러면 `index.html`의 `FIREBASE_CONFIG` 값이 2단계 값과 같은지 봐요. |
| 이벤트를 읽을 권한이 없어요 | 3단계 규칙을 붙여 넣고 **게시**했는지 확인해요. |
| 코드가 맞지 않아요 | 대·소문자를 확인하고, 4단계 계정 이메일이 `admin@seohaering.app`인지 확인해요. |
| 저장하지 못했어요. 코드를 다시 입력해 주세요 | `firestore.rules`의 이메일 목록과 관리자 계정 이메일이 같은지 확인해요. |
| 컴퓨터에서 `index.html`을 더블클릭했어요 | 자동으로 사이트 주소(GitHub Pages)로 넘어가요. 고친 파일은 GitHub에 올려야 사이트에 반영돼요. |
| 고쳤는데 사이트가 그대로예요 | 위 '고친 파일 올리기'의 2~3번을 봐요. |

## 관리자 여러 명이 쓰기

- 같은 코드를 관리자끼리 함께 알고 있으면 돼요.
- 관리자마다 따로 코드를 주고 싶으면 Authentication에서 계정을 더 만들고(예: `teacher@seohaering.app`), `firestore.rules`의 이메일 목록에 추가한 뒤 다시 **게시**해요.
  `["admin@seohaering.app", "teacher@seohaering.app"]`
  (단, 지금 서해링 화면은 `admin@` 계정의 코드만 확인해요.)

## 나중에 www.seohaering.com 같은 주소를 쓰고 싶다면

도메인을 산 뒤, 저장소 **Settings → Pages → Custom domain**에 주소를 적고,
도메인 판매 사이트에서 GitHub가 알려 주는 DNS 설정을 하면 돼요.
